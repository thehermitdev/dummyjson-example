# 04 — Todos / Task Management Module Roadmap

> DummyJSON เรียก resource นี้ว่า `todos` แต่ใน Admin UI เราจะสื่อสารกับผู้ใช้ว่า **Tasks** บทนี้จึงสอนทั้งการแปลง API language ให้เป็น product language และการจัดการ cache เมื่อ Task ถูกสร้าง แก้ไข ลบ หรือเปลี่ยนผู้รับผิดชอบ

⬅️ ก่อนหน้า: [`03.carts.md`](./03.carts.md)  
➡️ ต่อไป: [`05.dashboard.md`](./05.dashboard.md)

---

## 1. API Domain vs Product Domain

```text
DummyJSON API        Admin UI
-------------        ----------------
todo                 task
todo.todo            task description
userId               assignee
completed            completion status
```

เราไม่จำเป็นต้อง rename API contract ทั้งหมดจนหลุดจาก upstream API แต่ UI copy ควรใช้คำที่ผู้ใช้เข้าใจ

### Principle

```text
Transport language != Product language เสมอไป
```

Client/contract สามารถใช้ `Todo` ตาม API ขณะที่ navigation และ headings ใช้ “Tasks”

# Phase 6 — Reassignment: จุดที่ต้องคิดมากกว่า CRUD ธรรมดา

## Step 6 — เข้าใจปัญหา

สมมุติ Task #10 เดิม:

```text
userId = 5
```

แล้วแก้เป็น:

```text
userId = 8
```

เราอาจมี caches:

```text
["todos", "list", { userId: 5, ... }]
["todos", "list", { userId: 8, ... }]
["todos", "list", { no user filter, ... }]
["todos", "detail", 10]
```

การ replace object ทุก list อย่างเดียวอาจทำให้ Task #10 ยังติดอยู่ใน list ของ User 5 ทั้งที่ assignee เปลี่ยนแล้ว

### Demo Strategy vs Production Strategy

Current example ใช้ broad replacement เพื่อให้ simulated CRUD เข้าใจง่ายและ current session ต่อเนื่อง

Production-grade refinement ควรทำ predicate-aware reconciliation:

```text
if list.userId === oldUserId
  -> remove task

if list.userId === newUserId
  -> insert task ตาม pagination policy

if list ไม่มี user filter
  -> replace task
```

นี่เป็นจุดที่ควรเรียนรู้ว่า:

> Query Cache ไม่ใช่แค่ object storage แต่สะท้อนผลลัพธ์ของ query conditions

# Common Mistakes

## 1. เรียกทุกอย่าง “Todo” ใน UI

API naming ไม่จำเป็นต้องเป็น product copy  
แก้: UI ใช้ Task/Assignee/Completed ที่อ่านง่าย

## 2. Todos feature fetch Users ใหม่เอง

แก้: reuse Users Directory

## 3. Assignee filter เป็น local state อย่างเดียว

แก้: `userId` เป็น URL state

## 4. ใช้ debounce กับ Assignee select

ไม่จำเป็น เพราะ select เป็น discrete intent

## 5. Update task แล้ว patch detail อย่างเดียว

ผล: list เก่า  
แก้: reconcile lists + detail

## 6. Reassignment ไม่คิด filtered caches

Production system ต้องพิจารณา old/new assignee list membership

## 7. Delete แล้วไม่ remove detail cache

ผล: navigation กลับ id เดิมอาจเห็น stale object
